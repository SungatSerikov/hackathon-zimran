# CASE_TEMPLATE — как писать дело

Этот файл можно целиком вставить в GPT/Claude вместе с идеей дела. Результат — JSON, который движок примет без правок (формат — `SPEC.md` §5).

## Порядок работы

1. **Сначала граф на бумаге, потом текст.** Ответ → улики, которые его доказывают → откуда игрок узнаёт о каждой улике → с чего он начинает.
2. Запиши **цепочку решения**: стартовый документ → запрос → новый документ → запрос → … → 2 ключевые улики.
3. Добавь **ложные следы** (1–2): правдоподобная версия, которую улики опровергают.
4. Только потом пиши тексты документов.
5. Прогони `npm run validate`. Дай сыграть человеку, который сюжет не знает.

## Правила честного дела

- **Одно решение.** Ответ «кто + как» однозначно следует из улик, а не из догадки.
- **Каждая зацепка видна.** Если игрок должен искать телефон, этот телефон написан в тексте открытого документа (иначе движок не пустит запрос — это защита от перебора).
- **Конкретика**: даты, суммы, номера заказов, телефоны, адреса. Именно на них строится поиск и сверка.
- **Противоречие — двигатель дела.** Минимум одно место, где показания или документы не сходятся (дата, сумма, подпись, номер).
- **Ложная версия** должна выглядеть правдоподобно до одной конкретной улики.
- **Реализм США**: доллары, формат дат MM/DD/YYYY, телефоны вида (555) 0XX-XXXX (вымышленные, диапазон 555-01XX), вымышленный городок и компании. Никаких реальных компаний и людей.
- **Полезный подтекст** (не лекция): игрок привыкает сверять суммы, даты, условия договора, искать подтверждение у третьей стороны.

## Размеры

| | Учебное | Основное |
|---|---|---|
| Время | ~5 мин | 10–15 мин |
| Персонажи | 3 | 4–6 |
| Документы всего | 5–7 | 10–15 |
| Стартовых | 2–3 | 3–4 |
| Шагов поиска до решения | 2–3 | 4–6 |
| Ложных следов | 1 | 2 |
| Версий «как» | 3 | 4 |

Учебное дело должно **явно учить механике**: первый стартовый документ подсказывает, что имя компании можно ввести в поиск.

## Промпт для GPT

```
Ты — сценарист детективных головоломок. Напиши дело для браузерной игры
по формату ниже. Сеттинг: вымышленный американский городок, бытовая история
(счета, подписки, договоры, заказы, возвраты, переписка, возможный обман).

Идея дела: <вставь идею>
Сложность: <учебное | основное> (размеры — в таблице выше)

Сначала выдай:
1) Ответ (кто + как) и почему он однозначен.
2) Цепочку решения: стартовый документ → запрос → документ → ... → 2 ключевые улики.
3) Ложные следы и какая улика их опровергает.
Потом выдай JSON строго по схеме (ниже). Требования:
- каждый ключ из searchIndex.keys дословно встречается в поле text
  хотя бы одного документа, который игрок к этому моменту уже открыл (или в brief);
- requiredEvidence — id документов, которые доказывают ответ;
- в solution.methods ровно <3|4> версии, одна правильная;
- поле text каждого документа = плоский текст всего, что видно в документе.
Схема: <вставь §5 и §5.1 из SPEC.md>
```

## Чек-лист перед отдачей в код

- [ ] Цепочка решения проходится только по видимым зацепкам.
- [ ] Ответ нельзя угадать из `brief` без поиска.
- [ ] Все id уникальны, все ссылки существуют.
- [ ] Суммы и даты в разных документах согласованы (кроме намеренного противоречия).
- [ ] `explanation` объясняет решение в 3–5 предложениях и называет ключевые улики.
- [ ] Валидатор зелёный; человек со стороны решил дело.
