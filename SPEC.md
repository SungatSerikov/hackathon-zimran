# SPEC — детективная игра (Business Cup 2.0)

> Рабочее название: **Case Desk** (заменить, когда утвердите).
> Дедлайн сдачи: **15.11.2026, 12:00 (Астана)**. Сдаём: PDF-дек ≤10 слайдов, живую ссылку без логина, публичный GitHub.

## 1. Продукт в одном абзаце

Браузерная детективная игра для занятых взрослых в США (25–45). Игрок получает папку с материалами бытового дела (счета, договоры, переписка, заказы), сам вводит зацепки во **внутриигровой поисковик**, открывает новые материалы, собирает улики и выдвигает обвинение. Сессия 5–15 минут. Сейчас — одиночное прохождение готовых дел + глобальный рейтинг по каждому делу. Онлайн-дуэли — анонс «скоро».

## 2. Приоритеты

| Приоритет | Что | Почему |
|---|---|---|
| **P0** | Полный игровой цикл на 2 делах (учебное + основное): папка → поиск → улики → обвинение → результат с разбором | 40% оценки — «работает end-to-end» |
| **P0** | Валидатор дел (скрипт + тест): решение достижимо, нет тупиков | Доказывает, что ядро не захардкожено; страхует сценаристов |
| **P0** | Деплой на Vercel, без логина, работает на мобильном | Pass/fail |
| **P1** | Рейтинг по делу (Supabase, анонимный ник). Без env-переменных — локальный фолбэк | Соревновательность и возвращаемость |
| **P1** | Экран «Онлайн-дуэль — скоро» с кнопкой «Сообщить мне» и счётчиком интереса | Анонс + сигнал спроса для питча |
| **P1** | **Сейф с деньгами**: гонорар за раскрытое дело, баланс, история; **телефон информатора** — платные подсказки (§8.1) | Прогресс «зачем вернуться завтра» + точка монетизации |
| **P1** | Архивный шкаф с заблокированными «премиум»-делами + пейволл-модалка | Показывает модель монетизации |
| **P2** | Stripe Payment Link в тестовом режиме, звуки, анимации, «поделиться результатом» | Полировка |

Чего **не** делаем: логин, живой мультиплеер, генерация дел LLM в рантайме, мобильное приложение.

## 3. Стек

- Vite + React + TypeScript, Tailwind CSS.
- Состояние: Zustand (или useReducer) + localStorage для прогресса (всё в try/catch).
- Дела — JSON-файлы в `src/cases/*.json`, валидируются при сборке.
- Тесты: Vitest (движок поиска, валидатор, подсчёт очков).
- Рейтинг: Supabase (одна таблица), ключ только `anon`, RLS.
- Хостинг: Vercel. Секретов во фронтенде нет.

## 4. Экраны

1. **Главное меню** — название, «Играть», «Онлайн-дуэль (скоро)», «Как играть».
2. **Список дел** — карточки: учебное, основное, 2–3 заблокированных премиум (замок → пейволл). Показ лучшего результата и статуса «раскрыто».
3. **Стол детектива** (основной экран) — пиксельная сцена стола, каждый предмет кликабелен (раскладка и ассеты — `ASSETS.md`):
   - **Монитор** → поисковик (поле + история запросов + результаты). Открывается крупно поверх сцены.
   - **Папка с делом** → список открытых материалов (новые с жёлтым стикером); клик по документу → **просмотрщик** (документ «выезжает» на стол). Рендер по типу: чек, договор, переписка, письмо, объявление, выписка, заметка. Кнопка «📌 В улики».
   - **Пробковая доска / блокнот** → закреплённые улики.
   - **Часы** → таймер дела.
   - **Календарь** → «сегодняшняя» дата в мире игры (для сверки дат в документах) + стрик дней.
   - **Кружки кофе (3)** → жизни.
   - **Сейф** → деньги игрока (§8.1): клик открывает сейф — баланс, последние гонорары и траты. Спрайт `safe_open` с пачками купюр, если баланс > 0.
   - **Телефон** → «позвонить информатору»: платная подсказка (§8.1).
   - **Архивный шкаф** → архив премиум-дел (заблокированы → пейволл).
   - **Лоток со штампами** → вердикт (см. п. 4).
   - Документы — текст в читаемом пиксельном шрифте, рендерятся кодом (не картинкой).
   - На мобильном (<768px) — без сцены: вкладки Папка / Документ / Поиск / Улики / Вердикт.
4. **Вердикт** — каждое дело это **жалоба клиента**, бюро решает: **APPROVED** (жалоба обоснована, клиенту вернуть деньги) или **DENIED** (клиент неправ / обманывает).
   - Шаг 1: поставить штамп APPROVED / DENIED на заявление клиента (анимация штампа).
   - Шаг 2 (обоснование, чтобы штамп нельзя было угадать 50/50): **кто виноват** (персонаж) → **как** (одна из версий) → **2 улики** из доски.
   - Засчитывается, только если верны штамп, виновник, версия и улики.
   - Неверно: −1 кружка кофе, +60 с штрафа, подсказка «чего-то не хватает» (без раскрытия ответа). 0 кружек → дело провалено, показ разбора.
5. **Результат** — очки и разбивка, **гонорар** (анимация: купюры летят в сейф), разбор дела (объяснение + цепочка ключевых находок), ник → в рейтинг, топ-10 по делу, «Сыграть следующее».
6. **Онлайн-дуэль (скоро)** — описание будущего режима, кнопка «Сообщить мне», счётчик «N детективов ждут» (Supabase; без неё — локально).
7. **Пейволл** — «Detective Pass»: архив дел, новые дела каждую неделю, **безлимитные подсказки**, разбор от автора, приватные лиги. Цена-плейсхолдер $4.99/мес. Открывается из шкафа (премиум-дело) и из телефона, когда не хватает денег на подсказку. Кнопка → Stripe test link или «скоро».

## 5. Формат дела (JSON)

```jsonc
{
  "id": "tutorial-double-payment",
  "title": "Двойная оплата",
  "difficulty": 1,                 // 1..3
  "estMinutes": 5,
  "premium": false,
  "gameDate": "10/12/2026",        // «сегодня» в мире дела — показывает календарь на столе
  "brief": "Клиентка утверждает, что дважды заплатила за ремонт...",
  "characters": [
    { "id": "c_client", "name": "Linda Park", "role": "Клиентка", "portrait": "linda.webp" }
  ],
  "documents": [
    {
      "id": "d_invoice",
      "type": "receipt",           // receipt | contract | chat | email | ad | bank_statement | note | record
      "title": "Счёт #4471",
      "initial": true,             // выдаётся в стартовой папке
      "body": { /* структура зависит от type, см. §5.1 */ },
      "text": "плоский текст документа для индекса и поиска упоминаний"
    }
  ],
  "searchIndex": [
    {
      "id": "s_company",
      "keys": ["FixRight Repairs", "fixright"],   // что игрок может ввести
      "kind": "company",           // name | company | phone | address | order | email | plate | other
      "reveals": ["d_ad"]          // документы, которые откроются
    }
  ],
  "claim": "Прошу вернуть $480 — я заплатила за ремонт дважды.",  // заявление клиента под штамп
  "solution": {
    "verdict": "APPROVED",         // APPROVED | DENIED
    "culprit": "c_contractor",
    "methods": [
      { "id": "m1", "text": "Ошибка банка: платёж прошёл дважды" },
      { "id": "m2", "text": "Подрядчик выставил второй счёт с другим номером" }
    ],
    "correctMethod": "m2",
    "requiredEvidence": ["d_invoice2", "d_bank"],  // любые 2 из этого списка
    "explanation": "Текст разбора для экрана результата"
  }
}
```

### 5.1 Тела документов (минимум)

- `receipt`: `{ vendor, number, date, items:[{name, amount}], total, paymentMethod }`
- `contract`: `{ parties[], date, clauses:[string] }`
- `chat`: `{ participants[], messages:[{from, time, text}] }`
- `email`: `{ from, to, date, subject, body }`
- `ad`: `{ headline, body, phone?, address? }`
- `bank_statement`: `{ owner, rows:[{date, description, amount}] }`
- `note` / `record`: `{ heading?, body }`

## 6. Поисковик (ядро)

- **Нормализация** запроса и ключей: lower-case, обрезка, схлопывание пробелов, удаление пунктуации; для `kind: phone` — только цифры (`(555) 123-4567` = `5551234567`); для `order` — только буквы и цифры.
- **Совпадение**: точное после нормализации; для ключей длиной ≥6 допускается опечатка (Левенштейн ≤1).
- **Защита от перебора**: запись `searchIndex` доступна, только если хотя бы один её ключ (нормализованный) **встречается в `text` уже открытого документа** или в `brief`. Иначе — «Нет записей».
- Результат: показать найденные документы, добавить их в папку (подсветить «новое»), записать запрос в историю. Повторный запрос — «уже в папке».
- Счётчик поисков учитывается в очках.

## 7. Валидатор (`scripts/validate-cases.ts` + тест)

Для каждого дела проверяет:
1. Схему (типы, обязательные поля, ссылки id существуют).
2. **Достижимость**: BFS от `initial`-документов по правилу §6 — все `requiredEvidence` и хотя бы 80% документов достижимы.
3. Нет записей поиска, которые никогда не станут доступны (предупреждение).
4. `verdict` ∈ {APPROVED, DENIED}, `claim` не пустой, `culprit` есть в `characters`, `correctMethod` есть в `methods`, методов ≥3.
5. Выводит отчёт: минимальная цепочка запросов до решения.

Запускается в `npm test` и `npm run validate`. Сборка падает при ошибке.

## 8. Очки

```
score = max(0, 1000 − секунды − 150·неверные_обвинения − 5·поиски_сверх_минимума − 50·подсказки)
```
Минимум поисков берётся из валидатора. Жизни: 3.

## 8.1 Деньги и подсказки (сейф + телефон)

Внутриигровая валюта — доллары бюро. Хранится в localStorage `cd.wallet = { balance, history: [{ts, caseId, amount, reason}] }` (все чтения/записи в try/catch). Стартовый баланс **$100**.

**Гонорар** за раскрытое дело (провал → $0, повторное прохождение уже раскрытого дела → 25% гонорара):
```
base     = 100 · difficulty            // туториал $100, основное $200
speed    = time ≤ estMinutes      → +50% base
           time ≤ 1.5·estMinutes  → +25% base
clean    = 0 неверных обвинений   → +$50
fee      = base + speed + clean
```

**Подсказка «Позвонить информатору»** (клик по телефону во время дела), каждая стоит **$40**:
- Берётся следующий шаг минимальной цепочки поиска (её считает движок тем же BFS, что и валидатор, от текущего состояния: открытые документы + уже сделанные запросы), который игрок ещё не сделал.
- Уровень 1 (первый звонок по этому шагу): намёк — тип зацепки и документ, где она есть: *«Check the phone number in "Sponsored search result"»*.
- Уровень 2 (повторный звонок по тому же шагу): точный запрос: *«Search: (937) 555-0142»*.
- Если все шаги цепочки сделаны — подсказка про вердикт: *«You have enough. Pin the evidence and stamp the claim.»* (бесплатно).
- Не хватает денег → пейволл: Detective Pass (безлимитные подсказки) или пакет «$500 bureau cash» за $1.99 (Stripe test link / «скоро»).
- Каждая подсказка −50 очков (рейтинг остаётся честным).

**Сейф (экран)**: крупный баланс, последние 10 записей истории, кнопка «Пополнить» → пейволл. Модуль: `src/engine/wallet.ts` (+ тесты: начисление гонорара по формуле, списание, нехватка денег), `src/engine/hint.ts` (+ тест: подсказка на обоих делах ведёт по цепочке до решения).

## 9. Supabase (P1)

```sql
create table scores (
  id uuid primary key default gen_random_uuid(),
  case_id text not null,
  nickname text not null check (char_length(nickname) between 2 and 20),
  score int not null check (score between 0 and 1000),
  time_ms int not null,
  wrong int not null,
  searches int not null,
  created_at timestamptz default now()
);
create table waitlist_clicks (id uuid primary key default gen_random_uuid(), created_at timestamptz default now());
alter table scores enable row level security;
alter table waitlist_clicks enable row level security;
create policy "read scores" on scores for select using (true);
create policy "insert scores" on scores for insert with check (true);
create policy "insert clicks" on waitlist_clicks for insert with check (true);
create policy "count clicks" on waitlist_clicks for select using (true);
```
Env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. Без них — рейтинг и счётчик локальные (localStorage). Античит не делаем (честно пишем в README).

## 11.1 Визуал (кратко, подробно — `ASSETS.md`)

- Пиксель-арт, базовое разрешение сцены **480×270**, масштаб целым числом (×2/×3/×4), `image-rendering: pixelated`, letterbox по краям.
- Сцена = фон стола + отдельные спрайты предметов (PNG с прозрачностью), кликабельные зоны в координатах базового разрешения → проценты.
- Наведение на предмет: обводка 1px + подпись. Анимации: штамп, выезд документа, пар от кофе (опционально).
- Шрифты: заголовки — `Silkscreen` или `Press Start 2P`; текст документов — `VT323` или `Pixelify Sans` (читаемость важнее стиля).
- Вдохновение (раскладка стола, папка документов, штамп-вердикт) — жанровое; **арт, палитра, интерфейс и названия — свои**, ничего не копируем из чужих игр.
